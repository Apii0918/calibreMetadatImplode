# GitHub 來源庫建立與版本檢查指南

適用於 GitHub Plugin Updater **0.3**。本工具支援公開 GitHub 庫：自建來源使用本文的 JSON 清單；kiwidude68/calibre_plugins 可直接使用內建[前綴發行規則](./PREFIX_RULES.md)，不要求上游改動。AZW6 Image Merge 則使用[單庫單外掛規則](./SINGLE_RULES.md)。其他無清單來源尚未提供通用規則編輯器。

## 一、建立來源庫

同一個庫可以放一支或多支外掛，維護原始碼、README、CHANGELOG 與打包腳本，例如：

```text
my-calibre-plugins/
├── My Plugin/
│   ├── README.md
│   ├── CHANGELOG.md
│   └── src/
│       ├── __init__.py
│       └── ...
├── build_release.py
├── plugins.json
└── dist/                    # 產物，不提交 Git
```

每支外掛先決定三項識別資料：

| 欄位 | 範例 | 規則 |
| --- | --- | --- |
| 外掛固定 ID | `example.my-plugin` | 同一維護分支內長期固定，不包含版號。 |
| 來源 ID | `github:example/my-calibre-plugins` | `github:` 加小寫的 owner/repo，清單與包內身分檔必須一致。 |
| calibre 名稱 | `My Plugin` | 與外掛類別的 `name` 完全一致，用來對應已安裝項目。 |

原始碼中的 `version` 使用數字 tuple，例如 `(1, 2, 3)`，JSON 寫成 `[1, 2, 3]`。比較時逐段按數字比較，不按字串排序；`1.10` 大於 `1.2`。本倉庫上游修訂版沿用「完整上游版號加本地修訂段」，自研版號獨立管理。

整合庫的 Release 標籤（例如 `v1.3.28`）與各外掛版號分開管理，更新器不拿整合標籤當作外掛版號。0.3 不支援自動改名遷移，請維持名稱及固定 ID。

## 二、製作身分檔與清單

1. 更新程式宣告、外掛版號與說明。程式、翻譯或說明內容改變時，應遞增該外掛版號。
2. 將要發布的程式、資源與說明打包，按[清單規格](./MANIFEST.md#內容-sha-的確切算法)計算內容 SHA，排除身分檔本身及 ZIP 封裝資訊。
3. 在 ZIP 根層加入 `github-plugin-identity.json`，包含 `id`、`source`、`sha256`；其中 SHA 是第二步算出的內容 SHA。
4. 完成 ZIP 後再計算檔案大小與完整 ZIP SHA，填入清單。

清單中的每支外掛都必須提供：

| 欄位 | 內容 |
| --- | --- |
| `id`、`name` | 固定 ID 與 calibre 內部名稱。 |
| `version` | 外掛數字版號陣列。 |
| `minimum_calibre_version`、`supported_platforms` | 與程式宣告一致的最低版本及支援平台。 |
| `asset`、`size` | 同次 Release 的 ZIP 檔名及位元組大小。 |
| `sha256` | 與包內身分檔相同的內容 SHA。 |
| `package_sha256` | 完整 ZIP 的 SHA，供下載完整性校驗。 |

最外層必須有 `format: "calibre-github-plugins"`、`schema: 1`、`source` 及 `plugins` 陣列。完整 JSON 範例與內容 SHA 的確切算法見 [MANIFEST.md](./MANIFEST.md)。不能用名稱與版號文字的雜湊代替內容 SHA，也不能將完整 ZIP SHA 寫回 ZIP 自己的身分檔，否則會自我引用。

本倉庫以 `python -B build_release.py` 完成打包、身分檔與 `dist/plugins.json` 產生；腳本會清空 `dist/`，請勿在該目錄保存唯一資料。打包器固定 ZIP 項目的順序、時間戳及屬性，內容不變時重打包結果一致。維護者發布前同步根目錄 `plugins.json` 快照，產物留在 `dist/`。

若將本倉庫打包腳本改用於其他庫，必須一併修改身分檔與清單的來源 ID、固定 ID 前綴，以及 `PROJECTS` 內的來源與產物對應；不能保留本倉庫的 `samlaio` 識別冒充原來源。

## 三、發布與加入來源

1. 核對內外層說明、版號、CHANGELOG、清單及安裝包；先完成提交並推送。
2. 建立正式 GitHub Release，同批附上 `plugins.json` 與清單列出的所有外掛 ZIP。只建立 Git tag、只上傳 GitHub 原始碼壓縮檔、或只把 JSON 放在 main，都不足以作為 JSON 模式的更新來源；內建前綴模式使用各支外掛自己的正式發行。
3. 根目錄 JSON 是可閱讀及維護的快照；更新器實際讀取最新正式 Release 的 JSON，讓清單與附件保持同批。草稿及預發行不作為來源。
4. 在更新器「管理來源」貼上完整 GitHub 庫網址；Release、分支、檔案或 `.git` 網址也會辨識成所屬庫。儲存後按「檢查更新」。
5. 有正確身分檔的已安裝外掛可自動記住來源；舊包先勾選並綁定來源。同一支外掛只能追蹤一個來源。

GitHub 會把附件檔名中的空白轉成句點；清單可保留本機原檔名，工具會配對 GitHub 名稱。下載網址使用附件 ID 區分同名重傳，避免舊快取。

## 四、檢查更新的實際順序（JSON 模式）

1. 各來源獨立取得最新正式 Release 資訊與 JSON，不先下載 ZIP；某來源失敗不阻擋其他來源。
2. 依 calibre 名稱找到本機外掛，再核對固定 ID、來源及已保存的綁定。未安裝項目只列出，不提供首次安裝。
3. 有身分檔時，讀取其中的內容 SHA；舊包沒有身分檔時，才實算內容 SHA 作初次基準。
4. 本機內容 SHA 與來源 JSON 相同：顯示「內容相同」，不再比較版號。
5. SHA 不同：比較清單版號，較新提示「可更新」，同版提示可勾選重裝，較舊提示可勾選降版；相容性不符時另列提示。

重新綁定只改追蹤關係並記錄當下接受的本機 SHA，不改動已安裝檔案，也不會把本機 SHA 偷換成遠端值。因此綁定後仍可能顯示同版內容不同；甚至只清理行尾空白，也會改變內容 SHA。

## 五、勾選後如何安裝（JSON 模式）

勾選表示明確要求從所選來源強制安裝，內容相同、同版差異或較舊版都可以；同一外掛不可同時勾兩個來源。確認視窗列出狀態，使用者確認後才下載，並依序檢查：

1. ZIP 位元組大小、完整 ZIP SHA 與清單一致。
2. 包內固定 ID、來源及內容 SHA 與清單一致，且實算的新包內容 SHA 也一致。
3. 程式宣告的名稱、版號、最低 calibre 及平台與清單一致，而且目前環境相容；calibre 封鎖的外掛不能以強制安裝繞過。
4. 載入新版程式前保存舊包與登錄備份，再安裝並保留啟用／停用狀態；一般失敗回復原包與登錄。

成功後記錄新 SHA，清單只刷新成功項目的版號與狀態，不清空或重新抓取其他來源；至少一支成功後才啟用重啟按鈕。更新器自身也走同一流程，重啟後才載入新版。

備份路徑可在更新器設定，檔案以「外掛名稱-原版號.zip」命名，另有 `state.json`。不是完整設定快照，私有設定、書庫與書檔需另用 Plugin Backup。

## 六、驗證的界線

內容 SHA 用來判斷是否有變，完整 ZIP SHA 用來核對下載檔案；兩者不可互換。快速檢查信任本機身分檔，不是每次都掃描所有程式做防竄改檢查。SHA 也不是作者簽章；加入來源代表信任該來源的可執行程式。

GitHub API 的附件 `digest` 可作完整 ZIP 校驗的資料來源，本版已替 kiwidude 提供前綴標籤／附件 digest 模式，另支援 AZW6 單一發行模式；其他庫仍需清單，或後續新增明確的庫規則。官方 calibre 更新器也仍可能更新同名外掛，本工具不攔截它。

## 同名來源的處理

同名項目以來源 ID 加外掛固定 ID 分開列出，既有綁定不自動改變。calibre 按名稱安裝，不能讓同名版本並存；切換來源需明確選擇並確認，同一批不得勾選同一名稱的兩個來源。

## 單庫單外掛與預設來源

AZW6 Image Merge 以最新正式 Release 標籤作外掛版號，固定配對唯一的 AZW6ImageMerge.zip，沒有 digest 時明確退回版號比對，不以時間或附件 ID 代替 SHA。新增辨識規則不會自動訂閱該來源；全新安裝只預設我們的庫，更新或重裝保留使用者已設好的所有來源，包括空清單。

相容性仍以實際下載包為準；該上游 v1.0.0 在 calibre 9.19 的隔離載入測試缺少 imghdr，更新器會停止安裝並保留舊包，不會偷偷修補作者原包。完整流程見[單庫單外掛來源規則](./SINGLE_RULES.md)。
