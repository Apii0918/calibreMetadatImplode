# GitHub 外掛更新器（GitHub Plugin Updater）

版本：**0.3.3**；作者：**SamLiao & Codex**；授權：**GPL v3**；最低 calibre：**9.19.0**。本倉庫自行開發。

建立自己的更新來源或了解比對流程，請看[來源庫建立與版本檢查指南](./SOURCE_GUIDE.md)。

## 用途與安裝

從多個公開 GitHub 庫追蹤已安裝的 calibre 外掛。預設來源為 `SamLaio/calibreMetadatImplode`，每個來源可提供多支外掛。全新安裝預設只追蹤我們的庫；更新／重裝不覆蓋使用者既有來源，也保留空清單。0.2 新增 kiwidude68/calibre_plugins 的前綴發行模式，不要求上游提供我們的身分檔或 JSON。功能思路參考 [Obtainium](https://github.com/ImranR98/Obtainium) 的直接追蹤發行來源方式，沒有沿用其程式碼。

1. 以根目錄 `python -B build_release.py` 打包，安裝 `dist/GitHub Plugin Updater-zh_TW-release.zip` 並重啟 calibre。
2. 從「偏好設定 → 進階」第二列左側的「GitHub 外掛更新」開啟，關閉後回到偏好設定首頁；不提供工具列按鈕，入口使用循環箭頭與下載箭頭的專用圖示。
3. 按視窗左下方的「管理來源」，每行貼上一個完整 GitHub 網址，Release、分支與檔案網址會自動辨識所屬庫；仍相容 `owner/repo` 舊設定，介面統一顯示並保存完整庫網址；最多 30 個公開庫。
4. 按「檢查更新」。檢查只下載 Release 資訊與 JSON 清單，不下載外掛 ZIP；各來源失敗個別列出，其他來源繼續檢查。
5. 新包有來源身分檔時自動記住綁定；舊包或切換分支時，勾選對應項目，按「綁定勾選來源」確認。每支外掛只綁定一個來源，同名不自動接管。
6. 勾選欄標題為「全選」，點一下勾選所有可選項目，再點一下取消全選；未安裝的不可選項目保持不勾選。勾選已安裝項目，按「更新勾選」並確認後，才下載，依「自動備份」設定保留舊包，再強制安裝；可同版重裝、降版或改綁勾選來源。確認視窗會列出各項原狀態；同一支外掛只能勾選一個來源。完成後按「重新啟動 calibre」載入新版；按鈕預設灰色，至少一支外掛成功更新才啟用，包含更新器自身。清單不會清空或重抓，只更新成功項目的版號與狀態，其他項目及勾選保留。

外掛、目前版號、來源版號、GitHub 來源及狀態欄標題可點擊排序，再點切換升冪／降冪；版號按數字段比較，排序後保留勾選與正確外掛對應。

雙擊「GitHub 來源」欄可用瀏覽器開啟該庫；排序後仍對應正確來源。

未安裝項目的「目前版號」與「狀態」均只顯示「未安裝」。已安裝但無法載入的外掛才顯示「載入失敗」。

## GitHub Token 與限流

「管理來源」左下方的「設定 GitHub Token」可輸入選填的 Fine-grained PAT；選擇 Public repositories，維持唯讀即可。輸入採遮罩顯示，確定後保存，留空確定可清除；取消不變更設定。Token 只放在送往 `api.github.com` 的授權標頭，不會傳給 Release ZIP、JSON 附件或重新導向網址，也不放入背景工作檔。

Token **以明文儲存在本機 calibre 設定** `plugins/github_plugin_updater.json`；匯出完整設定備份時可能包含，請妥善保管。這個 Token 只用於提高公開庫 API 額度，本版仍不支援私有庫。

匿名 API 額度由同一出口 IP 共用，通常每小時 60 次；登入一般為每小時 5,000 次，仍可能遇到次要限流。API JSON 快取 5 分鐘，ZIP 不快取；快取及限流等待依 Token 分開，換 Token 後不沿用匿名冷卻。遇到 403／429 限流依 GitHub 的恢復時間或 Retry-After 等待；未提供時間時至少等待 60 秒，期間不再發出未快取的 API 請求。Token 無效或到期會另行提示，不會把一般權限錯誤誤認成限流。

部分或全部來源失敗時，介面明確顯示失敗，不能把空清單當成沒有更新。快取可能使最新發行延後最多約 5 分鐘顯示；額度用完時無法藉重按按鈕恢復。

## 單庫單外掛來源（AZW6）

0.3 新增 `https://github.com/HamsterExAstris/calibre-azw6-image-merge` 規則，從最新正式 Release 的 `v數字版號` 或數字標籤選版，精確尋找 `AZW6ImageMerge.zip`。只查 JSON，不先下載 ZIP；沒有 digest 時比較版號並提示校驗不足。附件 ID 只能提示重傳，不能代替 SHA。詳見[單庫單外掛規則](./SINGLE_RULES.md)。

實際上游 v1.0.0 原包在 calibre 9.19 的隔離載入測試因缺少 `imghdr` 失敗；更新器會保留舊包並回報失敗，不會替上游修改程式。此來源要由使用者自行加入，不預設訂閱。

## 前綴發行來源（kiwidude）

加入 `https://github.com/kiwidude68/calibre_plugins` 即自動套用內建 25 支外掛的名稱／前綴規則，分頁掃描正式 Release，依數字版號挑選各支最新版，接受 `prefix-1.2.3` 與 `prefix-v1.2.3`。先比較已保存的 GitHub 附件 digest；首次沒有基準或沒有 digest 時比較版號。檢查不下載 ZIP。找不到唯一附件或同版多個候選時標示錯誤，不猜包、不退回舊版。

同名外掛分來源列出；既有綁定不自動切換。同時勾選兩個同名來源會被擋下；選擇另一來源並確認強制安裝後才覆蓋及改綁，calibre 不支援同名版本並存。上游版可能取代本倉庫的翻譯與修正。

上游 ZIP 無身分檔也可安裝，但仍核對 GitHub digest、名稱、版號及實際 calibre／平台相容性。未提供 digest 時，確認視窗明確提示校驗不足，下載後計算本機 SHA 留存，不宣稱與作者摘要一致。完整規則見[前綴來源規則](./PREFIX_RULES.md)。

## 身分、SHA-256 與版號（JSON 來源）

每個 ZIP 的 `github-plugin-identity.json` 保存固定 `id`、`source` 與內容 `sha256`。本機設定 `plugins/github_plugin_updater.json` 保存來源及綁定。固定 ID 不隨版號改動；0.3 不支援外掛改名遷移。更新器本身也列入清單，沿用同一流程並在獨立程序安裝，重啟後才載入新版。

1. 讀取本機 ZIP 身分檔的內容 `sha256`，與清單 `sha256` 比較；有身分檔時不重新掃描外掛內容。舊包沒有身分檔才計算內容 SHA 作為初次基準。相同便結束，不比較版號。
2. SHA 不同，才比較 JSON 的版號及相容性。較新版提示「可更新」；同版不同 SHA 提示「同版內容不同（可勾選重裝）」；較舊版提示「遠端較舊（可勾選降版）」。這是檢查結果，不會自動下載或安裝。
3. 手動勾選即表示要求從該來源強制安裝，包括內容相同、同版不同內容或較舊版；確認後仍須通過下載完整性、身分、程式宣告與相容性檢查。來源有實際變更仍應遞增版號；強制重裝不是把不同內容視為相同。
4. 下載後再次檢查大小、完整 ZIP 的 `package_sha256`，實算內容 SHA 並核對身分檔與清單，再核對包內 ID／來源、程式宣告名稱／版號／相容性，避免清單與附件不符。ZIP 驗證通過之前不載入其程式。

內容 SHA 依路徑排序，將每個檔名、內容長度與解壓後內容納入計算；排除身分檔本身、目錄項目、ZIP 時間戳與壓縮屬性，避免自我引用，也不受昨天或今天重包影響。另以完整 ZIP 計算 `package_sha256`，只作下載完整性驗證。打包器仍固定時間戳、權限與順序，相同內容可重現相同 ZIP。程式、翻譯或說明改變時，必須遞增版號。

綁定包含安裝時內容 SHA。若其他更新器／手動安裝使來源身分消失或改變，需重新確認綁定；檢查後本機 ZIP 又變動則拒絕覆蓋。官方更新器仍可能更新同名外掛，本工具不攔截官方更新行為。

### SHA 與重新綁定的差別

重新綁定只記住外掛 ID 與追蹤來源，並記錄目前已接受的本機內容 SHA；不改寫包內身分 SHA，也不把本機 SHA 換成遠端值。因此綁定後若實際內容不同，仍會顯示同版差異。只有下載、驗證並成功安裝來源 ZIP 後，本機身分檔才會隨安裝包換成該來源版本的 SHA。

更新成功後，清單只刷新成功項目的目前版號與狀態，不重新抓取全部來源；新內容 SHA 同步記入綁定紀錄。更新器本身也使用同一流程，重啟 calibre 後才載入新版程式。

## 來源清單與發布

一般 JSON 來源的最新正式 GitHub Release 必須附上 `plugins.json` 及清單列出的 ZIP；不接受預發行或原始碼 ZIP。內建 kiwidude 前綴與 AZW6 單一發行規則不要求清單；其他沒有清單、也沒有內建規則的庫暫不支援。JSON 已包含版號，無須下載外掛才得知版本。

根目錄 `plugins.json` 是維護用的清單快照；`build_release.py` 產生 `dist/plugins.json`，發布時將該檔與同批 ZIP 一起上傳。更新器使用同一 Release 的清單與附件，避免 `main` 與已發布安裝包不同步。根目錄快照也須在發行前同步。

格式為 `calibre-github-plugins`、`schema: 1`。詳細範例及第三方來源製作方式見 [清單規格](./MANIFEST.md)。

## 備份與限制

「設定備份資料夾」右側的「自動備份」預設勾選，會記住選擇。勾選時，每支外掛更新前會在指定資料夾保留「外掛名稱-原版號.zip」與 `state.json`（登錄、啟用／停用與自訂設定），一般失敗回復原包與登錄，備份仍保留。按「開啟備份資料夾」可找到舊包，再由 calibre「從檔案載入外掛」手動還原。

取消勾選時不建立或保留這些備份；安裝期間僅在暫存目錄保留舊包以回復一般安裝失敗，作業結束即清除。成功更新後無法使用本次備份還原，亦不保證中途斷電或程序崩潰能回復。確認視窗會列出本次備份開關。

- 備份不是整個設定目錄的快照，不包含外掛私有 JSON、書庫或書檔；完整設定備份請使用 Plugin Backup。`state.json` 可能含自訂設定，請妥善保管。
- 安裝在獨立 calibre 背景程序執行，保留啟用／停用狀態；不讓操作介面因網路請求卡住。中途關閉主程式、斷電或磁碟損壞不能保證自動回復，請使用保留的備份。
- 不提供背景自動安裝、私有庫認證、無清單庫的猜測配對、新外掛首次安裝或跨來源自動選版。
- SHA 只能核對下載內容與來源清單一致，不是作者簽章。加入來源代表信任其可執行程式；僅允許 GitHub HTTPS 下載並限制大小與重新導向。
- 快速檢查信任身分檔的內容 SHA，並非每次檢查都驗證本機所有程式是否遭修改；一般更新會核對舊包內容；明確勾選的強制安裝允許修復本機內容差異，依「自動備份」設定保留舊包，並完整驗證下載的新包。
- 一般 JSON 來源的正式 Release 必須提供 `plugins.json`；kiwidude 前綴與 AZW6 單一發行模式例外。
